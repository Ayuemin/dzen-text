# База правил Дзена

`dzen-rules.json` — компактная база локальных эвристик, которую приложение использует без отправки статьи во внешние сервисы.

## Откуда берутся правила

Источник истины — официальная справка Дзена:

`https://dzen.ru/help/ru/requirements/rules.html`

GitHub Actions раз в сутки загружает эту официальную страницу и сравнивает нормализованный SHA-256 с последней обработанной версией. Если официальный текст не изменился, OpenRouter не вызывается и файл не переписывается.

Если источник изменился, workflow `Update Dzen rules database` передаёт **только официальный текст правил Дзена** модели через OpenRouter и просит преобразовать его в ограниченную структурированную базу: категории риска, сильные фразы-сигналы, основы слов, слова действия, контекст и исключения. Затем результат проходит локальную валидацию перед публикацией в репозитории.

Модель по умолчанию: `openai/gpt-oss-20b:free`. Если бесплатный endpoint временно недоступен, скрипт может использовать `openrouter/free` как бесплатный резервный маршрутизатор.

## Приватность

**Статьи пользователей в OpenRouter не отправляются.**

У updater-а нет канала получения пользовательских статей: он запускается в GitHub Actions и читает только публичную официальную страницу правил Дзена. Android-приложение скачивает уже готовый `dzen-rules.json` и выполняет анализ статьи локально на устройстве.

Отдельная онлайн-проверка орфографии через Яндекс.Спеллер — другая, явно отключаемая функция приложения и к обновлению базы правил отношения не имеет.

## Секрет

OpenRouter API key хранится только в GitHub Actions Secret с именем:

`OPENROUTER_API_KEY`

Ключ нельзя добавлять в APK, исходники, workflow или `dzen-rules.json`.

## Почему это не «список запрещённых слов»

Одно слово редко определяет нарушение. Поэтому schema 2 хранит контекстные признаки и исключения. Совпадение в приложении означает **возможный риск / проверить вручную**, а не утверждение о нарушении правил Дзена.
