# SPELL 01 — эксперимент локальной русской орфографии

Статус: **кандидат выбран по измерениям на физическом Android; Hunspell интегрируется в основной редактор**. Это закрывает выбор движка SPELL 01, но не заменяет полный корпус качества SPELL acceptance.

## Общий протокол

Оба кандидата проверялись отдельно от основного редактора. APK не имеют `INTERNET` permission. Для обоих использован одинаковый набор базовых корректных/ошибочных слов и одинаковый on-device benchmark. На телефоне фиксировались модель устройства, Android API, ABI, размер APK, время загрузки, приблизительная дополнительная Java-память, число принятых корректных слов, число найденных ошибок, первые пять подсказок и скорость словарных проверок.

После выбора движка отдельный полный корпус SPELL acceptance остаётся обязательным: 300 минимальных примеров + 50 размеченных фрагментов, split 80/20 и пороги из ТЗ. Малый probe-набор не заменяет этот корпус.

## Устройство

Физический Android: **TECNO LJ7**, Android API **36**, ABI **arm64-v8a**.

## Кандидат A — Morfologik/FSA

- Модуль: `spellprobe-morfologik`.
- Движок: `org.carrot2:morfologik-speller:2.2.0`.
- Русский словарь берётся как ресурс из `org.languagetool:language-ru:6.8`, зависимости LanguageTool runtime не подтягиваются (`transitive = false`).
- LanguageTool Russian speller использует ресурс `ru/hunspell/ru_RU.dict`; исходный README словаря указывает конвертацию из AOT и лицензию LGPL.
- Morfologik распространяется по permissive BSD-style license (см. upstream `LICENSE.txt`).
- На TECNO LJ7: APK 6 111 524 байта; init/load 18/18 мс; приблизительное изменение Java heap 1 949 696 байт; корректные 18/18; ошибок найдено 11/12; скорость 94 522 checks/s.
- Единственный пропуск малого набора: `обьяснение` было принято как допустимое слово.
- В ряде примеров ранжирование подсказок сильное: `превед → привет` первым, `севодня → сегодня` первым.

## Кандидат B — Hunspell/JNI

- Модуль: `spellprobe-hunspell`.
- Движок: Hunspell 1.7.2, upstream commit `2969be996acad84b91ab3875b1816636fe61a40e`.
- Интеграция: собственный JNI/CMake bridge, без стороннего Java wrapper.
- Словарь: LibreOffice `ru_RU.aff` + `ru_RU.dic`, pinned commit `32b006a2c22a4ac7e8ed3f03346f7b3d85a970a4`.
- Для приложения выбран вариант лицензирования Hunspell по MPL 1.1; полный upstream `COPYING.MPL` включается в APK подготовительным build-шагом. README словаря с copyright/license notice также включается в APK.
- APK собирается для `arm64-v8a`, `armeabi-v7a`, `x86_64`.
- На TECNO LJ7: APK 7 600 555 байт; init/load 738/744 мс; корректные 18/18; ошибок найдено 12/12; скорость 86 321 checks/s.
- `обьяснение` корректно поймано с подсказкой `объяснение` первой.
- Ранжирование подсказок не всегда лучше Morfologik: например, для `превед` в top-5 нет `привет`, а `сегодня` для `севодня` стоит вторым. Это отдельный риск качества подсказок и должен проверяться корпусом.

### Почему число памяти Hunspell нельзя сравнивать напрямую

Probe показывает `extraUsedMemoryBytesApprox = 57 104`, но этот показатель вычисляется через `Runtime.totalMemory() - Runtime.freeMemory()` и отражает Java heap. Основной словарь Hunspell загружается в native C++ память JNI, поэтому 57 КБ **не означает**, что Hunspell реально потребляет меньше памяти, чем Morfologik. Для A15 нужен отдельный Android memory benchmark процесса/PSS/native heap.

## Решение

**Выбран Hunspell 1.7.2 + LibreOffice ru_RU.**

Причины выбора на этапе SPELL 01:

1. Полнота малого телефонного набора: 12/12 ошибок против 11/12 у Morfologik при одинаковых 18/18 корректных словах.
2. Скорость 86 321 checks/s остаётся с большим запасом для редактора; разница с 94 522 checks/s не является практическим ограничением.
3. Увеличение probe APK примерно на 1,49 МБ допустимо по ограничениям проекта.
4. Холодная загрузка около 0,74 с заметно хуже Morfologik, поэтому основной app инициализирует Hunspell вне UI thread и переиспользует один экземпляр.
5. Качество ранжирования подсказок пока не считается доказанным: для него сохраняется отдельный acceptance-порог top-3 и расширенный корпус.

## Интеграция в основной app

Основной editor получает:

- native `hunspell-editor` для `arm64-v8a`, `armeabi-v7a`, `x86_64`;
- тот же pinned Hunspell commit и тот же pinned LibreOffice ru_RU, что использовались в probe;
- асинхронную инициализацию и batch-проверку через `AndroidSpelling`;
- отбрасывание устаревшего ответа по document snapshot/revision;
- исключение Markdown code, URL, link destination и путей через общую DOC05 document model;
- до пяти подсказок;
- базовые действия SPELL 02: «Исправить», «Пропустить», «Разрешить», «В словарь»;
- отдельный пользовательский словарь, который не перезаписывается при обновлении встроенного `ru_RU`.

Полный SPELL 02–04 и acceptance-корпус остаются отдельными этапами: управление личным словарём/импорт-экспорт, строгий режим `ё`, формальные правила дефисов/аббревиатур/чисел/названий продуктов и метрики precision/recall/top-3.
