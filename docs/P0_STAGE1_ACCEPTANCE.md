# Этап 1 P0 — протокол приёмки

Основание: `TZ_Text_Editor_2026-10-03.md`, разделы DOC 01–04, STYLE 01, DATA 01–02, PUB 01–03 и сценарии A01–A04, A11–A13.

Этот файл не утверждает, что весь этап принят. Автоматические проверки подтверждают только перечисленные свойства. Телефонная приёмка обязательна отдельно.

## Что реализовано в ветке

- P0-ядро `14-p0-core.js`: UTF-16 диапазоны, снимки документа, проверка устаревших результатов, транзакционное применение нескольких диапазонов справа налево.
- P0-адаптер `15-p0-foundation.js`: id/ревизия/хеш текста, версия настроек и правил в снимке анализа, запрет устаревшей замены, единый дополнительный контракт замечаний.
- Нативный sidecar `DocumentRevisionBridge`: сохраняет только id документа, возрастающую ревизию и хеш текста; содержимое статьи в sidecar не пишется.
- Поиск двух одинаковых русских слов подряд без JavaScript `\b`.
- Основная кнопка «Проверить» не зависит от экспериментального ONNX/NLI. Смысловая модель оставлена отдельным экспериментом.
- Пакет `editorial-rule-pack-v1` восстановлен как независимый модуль и не отключается смысловым экспериментом.
- Публикация имеет три явных режима: заголовок, текст без заголовка, всё. В режиме «всё» заголовок включается ровно один раз.
- HTML перед импортом очищается от script/style/iframe/object/embed, загрузочных атрибутов, обработчиков событий и внешних медиа. Ссылки остаются текстовыми данными.
- Основное хранение статей остаётся в `DocumentStore`: `.tmp/.bak`, восстановление после незавершённой замены, защитные версии перед опасными операциями.

## Автоматическая приёмка CI

### A01 — русские повторы

Проверяются:

- `слово слово`;
- `Это это`;
- повтор через перенос строки;
- `ёж, ЁЖ`;
- отсутствие ложного совпадения `слово другое слово`;
- отсутствие совпадения `тест тестирование`.

### A02 — UTF-16 координаты

Проверяются:

- эмодзи перед найденным фрагментом;
- `ё`;
- сохранение CRLF;
- комбинируемый символ `е + U+0301` при диапазонной замене.

### A03 — устаревшие результаты

Снимок считается действительным только при совпадении:

- document id;
- revision;
- text hash;
- settings version;
- rules version.

Изменение любого поля делает результат несовместимым.

### A04 — транзакционные исправления

Проверяются:

- несколько непересекающихся диапазонов;
- применение справа налево;
- неизменность исходного снимка;
- отказ при несовпадении исходного фрагмента;
- отказ при пересечении диапазонов.

### A11 — заголовок и копирование

Проверяются Markdown H1 и обычная первая строка. Режим «всё» содержит заголовок ровно один раз; режим «текст» не содержит заголовок; режим «заголовок» содержит только заголовок.

### A12 — безопасный HTML-импорт

Проверяется удаление активного/загрузочного HTML и сохранение читаемого текста/alt. Отдельный offline-инвариант проекта запрещает `INTERNET` permission.

### DATA 01/02 — инварианты хранения

CI проверяет:

- autosave debounce не более 1000 мс;
- немедленный flush при скрытии WebView и `Activity.onPause`;
- защитную версию перед очисткой и импортом;
- отмену перехода при ошибке защитного сохранения;
- `.tmp/.bak` и recovery в `DocumentStore`;
- подключение нативного моста ревизий.

## Обязательная телефонная приёмка

Сборка не считается принятой, пока на физическом телефоне не выполнены следующие шаги.

1. Ввести `слово слово`, `Это это`, `ёж ёж` и повтор через перенос строки. Проверить точное выделение второго слова.
2. Вставить `😀 ёж ёж` и убедиться, что переход по замечанию выделяет именно второй `ёж`.
3. Открыть замечание/замену, затем изменить текст. Старую замену применять нельзя; приложение должно потребовать обновить проверку.
4. Запустить анализ статьи A, затем переключиться на статью B. Результаты A не должны применяться к B.
5. Выполнить одну программную/массовую правку и один Undo. Должен восстановиться точный предыдущий текст одной операцией.
6. Проверить «Скопировать заголовок», «Скопировать текст», «Скопировать всё» для H1 и обычного текстового заголовка. В «всё» заголовок должен быть один раз.
7. Импортировать HTML со `script`, `onclick`, внешним `img` и обычными абзацами. Код не выполняется, внешние ресурсы не нужны, текст импортируется.
8. Набрать текст, подождать 1 секунду, закрыть приложение обычным способом и открыть снова. Текст должен восстановиться.
9. Повторить после принудительного закрытия приложения после завершения ввода.
10. Установить следующий APK поверх текущего. Статьи, последняя сохранённая редакция и номер ревизии должны сохраниться.

## Что не входит в приёмку Этапа 1

- полноценная русская словарная орфография;
- контекстная грамматика;
- морфологическая группировка словоформ;
- достижение бюджетов 50/150/500 тысяч знаков;
- качество экспериментального ONNX/NLI.

Это последующие этапы ТЗ и не должны маскироваться под выполненный P0.
